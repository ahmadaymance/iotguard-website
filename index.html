System Architecture

Five stages, under two milliseconds

From raw streaming packet capture at the physical interface to automated kernel firewall mitigation.

Stage 01

Suricata IDS

Packet Capture

Taps edge network interface and streams flow events over unix socket eve.json.

Stage 02

Feature Extractor

13-Dim Sliding Window

Aggregates 1-second rolling flow statistics with zero-allocation ring buffers.

Stage 03

LightGBM

1.78ms Inference

Gradient boosted tree ensemble classifies flow as benign, anomalous, or critical.

Stage 04

TreeSHAP

Additive Attribution

Extracts exact polynomial Shapley contributions for every flagged packet in microseconds.

Stage 05

Kernel Firewall

nftables / eBPF

Injects instant blacklist rules directly into the host network stack without userspace delay.

STAGE 01 INSPECTOR

Suricata Ingestion Engine

Protocol: UNIX Socket | Source: /var/log/suricata/eve.json
# Tail Suricata socket asynchronously with zero buffer overflow
import asyncio, json

async def stream_suricata_events(socket_path="/var/log/suricata/eve.json"):
    reader, _ = await asyncio.open_unix_connection(socket_path)
    while line := await reader.readline():
        event = json.loads(line)
        if event.get("event_type") == "flow":
            yield event

Why LightGBM + TreeSHAP Wins on IoT Gateways:

Neural networks demand dedicated GPU hardware or high vector compute overhead, scaling up packet latency to >12ms. LightGBM leverages leaf-wise histogram tree growth, executing inferences via compact conditional jumps that compile to bare-metal instructions. Pairing this with TreeSHAP guarantees $O(TLD^2)$ tree-path feature attribution without slow perturbation sampling.

Frequently Asked Questions

Common architecture, deployment, and security questions regarding IoTGuard.

IoTGuard utilizes LightGBM's pre-compiled C++ decision forest runtime combined with optimized NumPy ring-buffers. By constraining the feature space to 13 high-information-density statistical metrics, feature extraction requires less than 0.4ms and tree traversal takes ~1.3ms on an ARM Cortex-A72 processor, ensuring end-to-end processing well below 2ms.

KernelSHAP and LIME require thousands of repeated model perturbations and re-evaluations, which takes seconds per sample. TreeSHAP takes advantage of tree structure internally to compute exact Shapley values in polynomial time \(O(TLD^2)\), enabling per-packet explanations in under a few milliseconds.

IoTGuard implements a multi-tier threshold policy: scores between 0.70 and 0.85 enter a "Grace Period / Monitor" state requiring consecutive anomaly windows before enforcement. Hard instant-block rules are strictly reserved for critical scores (> 0.90) accompanied by high SYN/packet imbalance.
